# Telu Authentication & Dynamic Routing Flow (Frontend)

This document describes how the authentication mechanisms (standard JWT Credentials and Google OAuth) interact with the backend and route users based on database-managed roles.

---

## 🗺️ Authentication Routing Architecture

```mermaid
graph TD
    A[User visits Auth Page] --> B{Choose Method}
    B -- Google Sign In --> C[Authenticate via Google OAuth]
    B -- JWT Credentials Signup --> D[Submit Email + Password]
    B -- JWT Credentials Login --> E[Submit Email + Password]
    
    C --> F[POST /api/auth/google]
    D --> G[POST /api/auth/register]
    E --> H[POST /api/auth/login]
    
    F & G & H --> I{Server Response}
    I -- Success --  J[Set telu_user & telu_token in LocalStorage]
    
    J --> K{Check User Role}
    K -- client-* --> L[Redirect to /client/dashboard]
    K -- customer --> M{isProfileComplete?}
    
    M -- Yes --> N[Redirect to /customer/dashboard]
    M -- No --> O[Redirect to /auth/setup-profile]
```

---

## 🔐 Auth Providers (`src/components/auth-provider.tsx`)

The authentication provider (`AuthProvider`) acts as the state manager and handles client-side API requests:

* **Google Login (`login(email, role, undefined, googleIdToken)`)**:
  * Hits `POST /api/auth/google`.
  * Sends the `id_token` generated by Google OAuth client components.
* **Credentials Registration (`signup(email, password)`)**:
  * Hits `POST /api/auth/register`.
  * Passes `email` and hashed-ready `password` payloads.
* **Credentials Sign-In (`login(email, role, password)`)**:
  * Hits `POST /api/auth/login`.
  * Resolves login verification.
* **Profile Setup Wizard Completion (`updateProfile(details)`)**:
  * Hits `POST /api/auth/complete-profile`.
  * Submits custom contact details, address values, and usage plan details. Sets `isProfileComplete: true` in the DB.

### 🔌 Resilient Offline Fallback
To facilitate continuous frontend development even when the backend PostgreSQL database or Python service is offline, all auth functions automatically capture request errors and fall back to local simulated storage parameters (`telu_profile_<email>` in `localStorage`).

## 🎭 Role Redirection & Onboarding Guard

### 1. Dynamic Role Identification
The login handler inside [`src/app/auth/page.tsx`](file:///Users/vaaheesan/Desktop/CTS-NPN/telecom-frontend/src/app/auth/page.tsx) automatically reads the authenticated user's role returned directly from the backend response:
```typescript
const role = await login(email, "customer", password);
if (role && role.startsWith("client")) {
  router.push("/client/dashboard"); // Admin, billing agents, tech teams
} else {
  router.push("/customer/dashboard"); // Standard consumers
}
```

### 2. Lockout Guard
If a customer's profile is incomplete (`isProfileComplete == false`), they are blocked from raising complaints. When accessing the complaint module, they are shown a blockade view requesting them to complete their onboarding steps.
